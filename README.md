# Loon 彩云天气：本地定位、少通知与调用预算

原插件 URL（不变）：
https://raw.githubusercontent.com/panjin9395/loon-weather/main/CaiyunWeather.plugin

## 实际安排

基础请求每天 **24 个独立 slot**，不是 24 条通知：

- `30 6-21 * * *`：06:30–21:30，每小时半点，共 16 次。
- `0 7,8,9,12,16,17,18,20 * * *`：指定整点，共 8 次。
- 四场景直接在基础请求结果中分派，**不另建四场景 cron**。

| 上海时间 | 行为 |
|---|---|
| 07:30 | 今天出门：今日最低/最高、未来3小时已提供时段的最高降雨概率与带伞参考 |
| 12:00 | 仅新增/更新有效官方预警；没变化安静 |
| 17:00 | 回家/出行：未来3小时温度、天气、降雨概率 |
| 20:30 | 明日最低/最高，与今天 `(最低+最高)/2` 比较，绝对差≥5°C才标明显升降温 |
| 其他基础 slot | 无变化不通知；仅新/更新有效官方预警或可信天气明显变化 |

可信天气变化要求实时块 status=ok、明确带时区 obsTime（距查询≤60分钟、不晚于查询5分钟）、有效温度及服务器时间检查；与3小时内上次可信观测比较，温度变化≥5°C或雨雪状态改变才提醒。没有 obsTime 不猜新鲜度，因此通常只能做官方预警变化提醒。相邻相同天气不重复提醒；变化合在一个通知内，不为预警再弹第二个窗口。

机动 cron 是明确的 `15,45 7-20 * * *`：07:15–20:45。**触发不等于请求**，只有上次正式有效降雨/降雪或官方有效预警留下的检查窗口尚未结束才允许请求；无理由安静退出。雨雪窗口最多到观测后2小时；预警最多到本次有效检查后2小时，且不越过明确失效时间。失败不延长窗口。手动和条件机动检查合计默认每天最多 **3次**，不会额外请求凑数。22:00–06:00没有任何轮询。

cron 跟随 **Loon/设备时区**，应保持 Asia/Shanghai。脚本日期、当地日计数、跨月跨年与闰日固定使用现代上海 UTC+08:00（无DST），不依宿主时区。改变设备时区需自己调整 cron。iOS/Loon 可能延迟或漏触发；本脚本不承诺动态后台精确定时、不补跑错过 slot。

## 请求、预算和限制

每次许可的天气运行只请求一次 **v2.6 综合 weather**，同时拿实况、逐小时、逐日和预警：
`weather?lang=zh_CN&dailystart=0&hourlysteps=24&dailysteps=3&alert=true`。
不会拆成多个天气接口，也不使用真实用户 Token 做服务器测试。保留旧的可选腾讯城市/区名反查：仅本地已有 `token.tencent` 时可能另发地图请求，失败冷却1小时；它不属于彩云天气调用，不会输出街道。不填腾讯 key 不请求地图。

- 未配置额度：基础24次上限 + 手动/条件机动共享每日3次上限，合计最多27次本地尝试。手动不占正式slot，但占当天总尝试与机动，预留未运行的基础slot；预算低时先留四场景。动态日预算不足4时无法保证四场景全部请求，按时间顺序保留可负担的场景，绝不超出剩余估算。
- 网络失败、非法响应均在发出前计入**尝试**，不自动重试；失败slot不会同日自动再请求。缺Token/定位或无效坐标没有发出请求，不计尝试。定时失败安静，手动有脱敏提示。
- `caiyun_budget_v1` 独立本地持久化保存当日slot/机动slot、次数、累计尝试和少量无坐标天气状态；发出前写入并读回，不成功就不请求。隔天只换日计数，累计尝试不年度清零。
- 同日同slot顺序重复执行不会请求；旧 `scene=...` 任务恰好在对应场景时间也共享基础slot，避免旧/新cron重复。请更新插件移除旧独立场景任务。不要新建并行副本。
- **Loon持久化没有跨脚本进程原子CAS/锁保证**。先写读回只能降低顺序重复/失败风险，不能证明同时启动绝不竞态；同Token其他设备/脚本、重装清存储、崩溃和平台计费差异均无法由本机精确计数。
- 手动诊断明确标注「本地估算」，不是平台实际计费次数；不能以成功次数冒充计费。

### 可选本地滚动额度配置（不上传）

当前真实剩余次数和到期日**未知**；未读取平台、不声称套餐已绑定或已生效。10000次/365天只是预算模板，不能当已知剩余。仅有需要时，在现有 BoxJS `caiyun` 对象中合并以下二选一字段，保留已有token/location，所有真实数据只在手机本地填写：

```json
{"quota":{"remaining":10000,"expiry":"2027-10-17"}}
```

上面只是示例日期和数量，必须改成平台真实值。首次使用该组配置时把 remaining 当作当前余额快照，之后扣除本地新尝试；更改配置会建立新快照，相同配置不会重新充余额。expiry 为上海当地**含当日**截止。

或使用真实套餐总额与实际开始日：

```json
{"quota":{"total":10000,"start":"2026-10-18"}}
```

总额模式固定365个含首尾当地日，结束日为 start+364天；减去本脚本保存的全部累计尝试，过期后不会每年重置。开始日期未来、非法日期/数字、配置不完整、余额为0、已到期时拒绝请求；移除quota字段才恢复默认日上限。

配置有效才用 `floor(估算剩余 / 含今天的剩余天数)` 滚动分配，日上限不超过27；日内已分配上限固定，次日重新算。请求前还检查估算余额，优先预留四场景，其余基础检查可被跳过；手动/机动只有预留全部后续基础slot后仍有余量才请求。

**过去已耗额度未知**，总额模式也不能还原安装之前或其他设备的使用，不能保证到期精确清零/恰好用完；请优先用平台真实 remaining+expiry 校准。不要发Token、坐标或带秘密截图到聊天/仓库。

## 已保留行为与隐私

- 定位仅存在手机本地。距离锚点3km以内（含边界）不换坐标与时间，超出3km才验证并更新。无法区分苹果天气当前位置与收藏城市，远处收藏城市仍可能换锚点。
- MITM仍仅 `weather-data.apple.com, api.weather.com, weatherkit.apple.com`。未改网络规则、定位脚本、3km逻辑。
- 失败不复用旧天气、不输出原始异常、Token、URL或坐标；无有效数据如实降级，缺明日不以今日替代。
- 观测更新时间只接受带时区 obsTime，没有则未知。server_time 单列接口响应时间，不能冒充观测。查询时间和通知生成时间独立标注。接口超过60分钟或明显未来停止预报建议/预警触发。
- 官方预警须 status=ok、active alerting/预警中、有效id/code/发布时间，过期/解除/拒绝记录不触发。按id+code+发布时间+可选更新时间本地去重（最多200版本）。更新记录可再次通知，不把持续预警反复弹窗。
- 正常 content=[] 表示本次API无有效记录，不保证当地无预警；content=[]且adcodes=null、缺块、denied为未知。概率单位0–100%，缺失不是0。权限不足不猜测。

## 手动和升级

手机只需**更新一次原插件，并在这次更新操作中刷新/清除该插件远程脚本缓存**。原 URL 不变，插件应为2条基础cron+1条条件机动cron，不再保留旧4条独立场景任务。不是每天让用户更新。

现有「彩云天气手动测试」按上海小时段预览，带固定文案能力摘要（实况/逐小时/逐日/预警），并显示当日本地估算。指定场景可用 `scene=night&preview=1`。手动预览消耗预算，但**不写正式slot、不消费预警/天气变化去重**，不会吞下次正式通知。不要用无preview的scene参数手动模拟正式场景。场景能力摘要不是购买凭证、字段缺失不证明权限不足。

原 `caiyun` 本地可选字段继续有效：
```json
{"scenes":{"morning":true,"noon":true,"evening":true,"night":true},"temp_change_threshold":5,"umbrella_probability_threshold":40}
```
false关闭该场景正式通知，手动仍可预览；温差阈值(0,30]、带伞概率阈值(0,100]，非法回默认。无新增BoxJS订阅UI，直接复用本地对象。
